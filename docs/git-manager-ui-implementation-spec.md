# Git Manager UI 落地规格

本文件用于约束后续实现，目标是严格贴近 `docs/git-manager-ui-concept.png` 的图二视觉稿。实现前先对照本规格，不再凭感觉微调。

## 基准画布

- 展示图画布：`1536 x 1024`
- 单个应用窗口基准：`520 x 444`
- 窗口比例：约 `1.17:1`
- 实际程序默认窗口建议：`1024 x 660`
- 最小窗口建议：`980 x 620`
- 不建议全屏式布局；所有页面按概念图的“紧凑桌面工具”比例设计。

## 总体结构

应用窗口由四块组成：

1. Windows 标题栏：系统原生，保持默认。
2. 主工作区：左侧导航栏 + 右侧内容区。
3. 底部状态栏：横跨整个窗口宽度。
4. 页面内容：每个左侧菜单对应一个独立页面，不把所有功能堆在概览页。

结构比例：

- 左侧导航栏：`64px`
- 右侧内容区：剩余宽度
- 内容区左/右 padding：`14px`
- 内容区上 padding：`10px`
- 卡片间距：`8px - 10px`
- 底部状态栏高度：`24px - 28px`

## 左侧导航栏

左侧栏必须严格贴近概念图：

- 宽度：`64px`
- 顶部 Logo 区：
  - 高度：`68px`
  - 背景：白色 `#ffffff`
  - 文本：`GM`
  - 字体：微软雅黑/Segoe UI，`15px - 16px`，加粗
  - 文本颜色：`#111827`
- 菜单区：
  - 背景：深蓝黑 `#0f172a`
  - 单个菜单项高度：`56px - 58px`
  - 图标在上，文字在下
  - 图标尺寸视觉约 `16px`
  - 文字尺寸：`10px`
  - 菜单项之间无大空隙
  - 不允许把菜单项均分整条侧栏高度
- 选中态：
  - 菜单项背景：`#334155`
  - 左侧高亮条：`3px`
  - 高亮条颜色：`#0ea5e9`
  - 文本/图标颜色：`#38bdf8`
- 未选中态：
  - 背景：`#0f172a`
  - 文本/图标颜色：`#cbd5e1`

菜单顺序固定：

1. 新建
2. 概览
3. 分支
4. 提交
5. 发布

## 顶部项目信息区

顶部信息区在所有页面保持一致。

- 区域高度：约 `108px - 116px`
- 内容区左侧起点与页面卡片对齐。
- 标题：
  - 文本：`Git Manager`
  - 字号：`16px - 18px`
  - 加粗
- 项目路径：
  - 标签位于输入框上方
  - 输入框高度：`28px - 32px`
  - 右侧按钮竖排：
    - `选择`
    - `刷新`
  - 两个按钮宽度一致：`52px - 58px`
  - 按钮高度：`32px`
- 仓库摘要：
  - 位于路径输入框下方
  - 单行显示：`仓库: Program_PM    分支: master    同步: 已同步`
  - 字号：`10px - 11px`
  - 仓库名加粗

## 页面规格

### 01 新建

布局：左右两列。

- 左列：项目信息卡片
- 右列：模板文件卡片
- 两列宽度接近 `45% / 55%`
- 卡片顶部对齐，高度一致

项目信息卡片：

- 标题：`项目信息`
- 字段：
  - 创建位置：输入框 + 浏览按钮
  - 项目名称：输入框
  - 创建后初始化 Git 仓库：checkbox
- 主按钮：`创建项目`
  - 蓝色填充 `#2563eb`
  - 宽度撑满主要输入区域
- 底部提示带信息图标，文字不超过两行。

模板文件卡片：

- 标题：`模板文件 (ModuleFiles)`
- 顶部按钮：`全选`、`全不选`、`刷新`
- 文件列表使用 checkbox
- 列表区域必须有垂直滚动条

### 02 概览

布局：三段。

1. 四个状态卡横排
2. 仓库配置 + 快捷入口横排
3. 工作流提示大卡片

状态卡：

- 四列等宽
- 高度：`86px - 92px`
- 卡片标题小字，内容加粗
- 图标位于上方或左上，不使用紫色边框

仓库配置：

- 位于左侧，约占 `60% - 65%`
- 字段：仓库名、默认分支
- 下方四个等宽按钮：刷新、检测远程、重置 Git、状态详情

快捷入口：

- 位于右侧，约占 `35% - 40%`
- 三个按钮横排：分支管理、提交同步、版本发布
- 分支管理：蓝色描边
- 提交同步：绿色描边或绿色填充
- 版本发布：紫色描边

工作流提示：

- 占满下方宽度
- 大面积留白允许存在，但顶部文字不得贴边。

### 03 分支

布局：上下三块。

1. 分支操作卡片
2. 分支列表卡片
3. 底部操作按钮条

分支操作：

- 第一行：切换到 combobox + `切换`主按钮
- 第二行：新分支输入框 + `创建并切换`按钮
- 信息提示行带小图标。

分支列表：

- 表格必须有纵向和横向滚动条
- 表头：分支、类型、上游、提交、日期、说明
- 表格高度约占页面主体 `50% - 60%`

底部按钮条：

- 四个等宽按钮：获取远程、检测远程、重置 Git、状态详情

### 04 提交

布局：上下三块。

1. 提交卡片
2. 同步卡片
3. 提交历史 / 操作记录

提交卡片：

- 提交信息输入框占主宽度
- `添加全部` 和 `提交` 按钮在右侧
- `提交` 为蓝色主按钮

同步卡片：

- 三个按钮横排：推送、拉取、获取
- 推送为绿色主按钮

历史区：

- 类似列表/日志表格，不做巨大空白文本框
- 右侧垂直滚动条
- 底部有 `刷新日志` 按钮

### 05 发布

布局：上下两块。

1. Release 列表
2. 创建 Release

Release 列表：

- 顶部显示 `Latest Release: v1.0.0 | Latest`
- 表格列：Release、状态、Tag、发布时间、来源
- 表格必须有水平滚动条

创建 Release：

- Tag + 标题同一行
- 说明单行
- 资产路径 + 浏览按钮同一行
- Draft、Prerelease checkbox
- 发布 Release 主按钮在右下角

- 侧栏深色：`#0f172a`
- 页面背景：`#f8fafc`
- 卡片背景：`#ffffff`
- 边框：`#d7dee8`
- 浅底：`#f8fafc`
- 输入框底色：`#ffffff`

## 字体系统

- 标题：微软雅黑 UI / Segoe UI，`12px - 14px`，Semibold
- 正文：微软雅黑 UI / Segoe UI，`10px - 11px`
- 辅助文字：微软雅黑 UI / Segoe UI，`9px - 10px`
- 表格文字：微软雅黑 UI / Segoe UI，`9px - 10px`

## 实现纪律

- 先完成静态 UI，再接功能。
- 每个页面先按本规格放假数据，确认比例后再绑定真实数据。
- 禁止为了塞功能而改变概念图布局。
- 左侧导航、顶部路径区、底部状态栏必须作为全局组件复用。
- 页面内按钮宽度必须统一，不允许同一行按钮一长一短。
- 表格必须显式配置滚动条。
- 状态栏只能显示短摘要，完整结果用弹窗或详情页。
